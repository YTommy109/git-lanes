ステージングされた変更を確認し、このプロジェクトの規約に沿ったコミットメッセージを提案する。

## 手順

1. `git diff --staged` でステージング済みの変更内容を確認する
2. `git status` で変更ファイルの一覧を確認する
3. 変更の種類から type を決定する

   | type | 選ぶ基準 |
   |------|---------|
   | `feat` | 新しい機能・画面・エンドポイントを追加した |
   | `fix` | バグを修正した |
   | `refactor` | 外部から見た動作を変えずにコードを整理した |
   | `test` | テストコードのみを追加・修正した |
   | `docs` | ドキュメント（`.md` など）のみを変更した |
   | `chore` | ビルド設定・依存関係・CI 設定を変更した |
   | `perf` | パフォーマンスを改善した（機能変更なし） |

4. 以下の形式でコミットメッセージを作成する

   ```
   <type>: <日本語の件名（〜する で終わる動詞形）>

   <日本語の本文（変更の背景・理由。複数の変更がある場合や理由が非自明な場合のみ記述）>
   ```

5. 作成したメッセージをユーザーに提案する。コミットは**実行しない**。

## 制約

- 件名は日本語。50 文字以内を目安とする
- 件名は「〜する」「〜を追加する」「〜を修正する」のような動詞形で終わる
- 本文が不要な場合（変更が自明）は件名のみでよい
- `Co-Authored-By:` トレーラーは付けない（ユーザーがコミット時に判断する）
