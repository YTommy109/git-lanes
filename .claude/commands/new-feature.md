新機能の実装を開始する。ブレインストーミング → 計画 → TDD 実装の順で進める。

## ステップ 1: ブレインストーミング

`superpowers:brainstorming` スキルを呼び出してから以下を行う。

- 機能の目的とユーザーへの価値を整理する
- `docs/specification.md` を参照して既存の機能要件との整合性を確認する
- `docs/architecture.md` を参照して影響するコンポーネントを特定する
- 技術的な実現方法の選択肢を列挙し、推奨案を提案する

ユーザーの承認を得てからステップ 2 に進む。

## ステップ 2: 実装計画

`superpowers:writing-plans` スキルを呼び出して計画を作成する。

計画には以下を含める。

- 変更するファイルの一覧（新規 / 修正）
- 各ファイルの変更概要
- テスト戦略（単体テストのケース一覧）
- 実装順序（依存関係の少ない順）

ユーザーの承認を得てからステップ 3 に進む。

## ステップ 3: TDD 実装

`superpowers:test-driven-development` スキルを呼び出して実装する。

### 実装時の制約チェックリスト（毎関数・毎ファイルで確認）

- [ ] 関数の行数 ≤ 30 行
- [ ] ファイルの行数 ≤ 150 行（テスト除く）
- [ ] ドックストリングが Google スタイルで日本語
- [ ] コメントが日本語
- [ ] 認知的複雑度 ≤ 10（分岐が多い場合は関数に分割）
- [ ] D3.js を使っていない（SVG は Jinja2 テンプレートで生成）
- [ ] JavaScript を書いていない（htmx + hyperscript で完結）
- [ ] Git 操作は pygit2 のみ（subprocess で git コマンドを叩かない）

## ステップ 4: レビュー

`superpowers:requesting-code-review` スキルを呼び出してレビューを依頼する。

完了後、`/commit` コマンドでコミットメッセージを生成する。
