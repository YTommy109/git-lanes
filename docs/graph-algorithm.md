## 用語一覧

| グループ | 用語 | 定義 |
|---|---|---|
| **レーン** | レーン | グリッドの縦列ひとつ分。幅は 30px 固定 |
| | ブランチレーン | ブランチ名ラベルを持つレーン。レーン番号 1, 4, 7, …（3 本おき）に配置される |
| **ノード** | コミットノード | グラフ上にコミットを表す塗り潰し円。ブランチの色で描画される |
| | 分岐ノード | ブランチが派生した起点となるコミット。塗りつぶしなしの丸印で描画される |
| | マージノード | 複数ブランチが合流したコミット（マージコミット）。塗りつぶしなしの丸印で描画される |
| | ダミーノード | コミットがない行にブランチの存在を示すために置く小さい円。破線でコミットノードと接続する |
| | エンプティノード | |
| | ジョイントノード | ブランチが別レーンのコミットを指す場合に、接続線の折れ点として置く不可視の点。丸印は描画しない。破線が通過する中継点として機能する |

## 座標系とグリッド

碁盤の目（グリッド）を座標系とし、各コミットをセルに配置する。

- **レーン**: 横軸（X）。左から 1 始まりで番号を振る。ブランチの流れが縦に並ぶ
- **行**: 縦軸（Y）。上が新しい。トポロジカルソート順に 0 から連番を振る
- **グリッドサイズ**: 縦横ともに 30px
- すべてのコミットは `(レーン番号, 行番号)` のセルにひとつだけ配置される

### レーン番号とブランチの対応

| 種別 | レーン番号 |
|---|---|
| ブランチレーン（ブランチ名ラベルあり） | 1, 4, 7, … （3 本おき固定） |
| 削除済み・名なしブランチ | 2, 3, 5, 6, … （中間レーン） |

ブランチレーン間の距離: 30px × 3 = 90px。

### SVG 座標への変換

- レーン N の cx: `20 + N × 30`（例: レーン 1 → 50、レーン 4 → 140）
- 行 M の cy: `72 + M × 30`（例: 行 0 → 72、行 1 → 102）
- cy=72 より上（cy=50 付近）はブランチ名ラベル領域として確保する

## 描画ルール

### 斜め線のルール

斜め線は隣接する **1 行の間**でのみ引く。複数行をまたぐ場合はジョイントノードを経由して 1 行ずつに分割する。

### ノードの描画仕様

| ノード | 描画 |
|---|---|
| コミットノード | r=7 の塗り潰し円。ブランチ色、白ストローク幅 2 |
| 分岐ノード | r=7 の塗りつぶしなし円。ブランチ色ストローク幅 2、fill=none |
| マージノード | r=7 の塗りつぶしなし円。ブランチ色ストローク幅 2、fill=none |
| ダミーノード | r=3 の小さい円。破線で次のコミットノードと接続する |
| ジョイントノード | 丸印なし。斜め線の折れ点として機能する不可視の中継点 |

### ノードタイプの判定

コミット C を配置するとき、以下の優先順で判定する。

| 条件 | ノードタイプ |
|---|---|
| `len(C.parents) >= 2` | マージノード |
| C が複数レーンの始点になる（C.hash が複数のレーンの親として参照される） | 分岐ノード |
| ブランチ先端が行 0 にない場合に先端より上の行へ補完配置する | ダミーノード |
| それ以外 | コミットノード |

マージノードと分岐ノードは重複することがある（同じコミットが両方の性質を持つ場合）。

### エッジの種類

| 種類 | 描画 | 使用場面 |
|---|---|---|
| 実線 | `stroke-dasharray` なし | コミット間の実際の親子エッジ |
| 破線 | `stroke-dasharray="4,3"` | ダミーノードまたはジョイントノードが関与する接続 |

### ダミーノードの配置条件

ブランチ先端コミットの行番号が 0 より大きい場合（他ブランチにより上の行が先に埋まった場合）、
行 0 にダミーノードを置き、破線で先端コミットまで接続する。

### ブランチ名ラベル

- ブランチレーン上部に −45° 回転して表示する
- 同一コミットを指す複数ブランチは横に並べて表示する
- 削除済みブランチにはラベル・ダミーノードを表示しない
- ラベルの色は `#555`（ブランチ色は使わない）

### ブランチ色

ブランチ名・プレフィックスに関係なく、登場順（インデックス 0〜7）にローテーションして割り当てる。

## レイアウトアルゴリズム

### 入力

- 全コミットのリスト（新しい順にトポロジカルソート済み）
- 各コミットの親ハッシュリスト（マージコミットは複数）

### データ構造

`active_lanes`: 各レーンの末尾コミット（まだ親が確定していない最古のコミット）を持つリスト。

### レーン割り当て

```
for commit C in sorted_commits（新→古）:
    for lane in active_lanes（左から順に）:
        if C.hash in lane.bottom.parent_hashes:
            lane に C を追加し lane.bottom を C に更新
            break
    else:
        新しいレーンを作り C を配置し active_lanes に追加する

    if C.parents が空（root コミット）:
        C を末尾に持つレーンを active_lanes から削除する
```

レーンの照合は左から右へ順に行い、最初に一致したレーンに配置する。

### 新規レーンの番号決定

新しいレーンを作る際、そのブランチに名前があるかどうかで番号を決める。

- **ブランチ名あり（ブランチレーン）**: 未使用の 1, 4, 7, … の中で最小の番号を割り当てる
- **削除済み・名なし（中間レーン）**: 隣接するブランチレーン間の未使用番号（2, 3, 5, 6, …）から割り当てる

### マージコミットの親の扱い

マージコミット C の `parent_hashes = [p1, p2, ...]` に対して：

- **第1親 p1**: C と同じレーンに引き続き配置する（同レーン内の縦エッジ）
- **第2親以降 p2, ...**: それぞれ別のレーンに属する。そのレーンから C へ斜めエッジで接続する

### 親チェックの向き

Git のコミットは「自分の親ハッシュ」を持つ。新→古の順で処理するため、
レーンの末尾（新しい側）が今見ているコミット（古い側）を親として知っているかを確認する。

```python
C.hash in lane.bottom.parent_hashes
```

### 具体例 — 単純二分岐（マージなし）

```
main    : root ← B ← D   (D が最新)
feature : root ← C ← E   (E が最新)
```

| step | 処理 | active_lanes |
|---|---|---|
| 1 | D → レーン 1 に配置 | `[lane1:[D]]` |
| 2 | E → lane1.bottom(D).parents=[B]、不一致 → レーン 4 を新規作成 | `[lane1:[D], lane4:[E]]` |
| 3 | B → lane1.bottom(D).parents=[B]、一致 → レーン 1 に追加 | `[lane1:[D,B], lane4:[E]]` |
| 4 | C → lane1.bottom(B).parents=[root]、不一致 → lane4.bottom(E).parents=[C]、一致 → レーン 4 に追加 | `[lane1:[D,B], lane4:[E,C]]` |
| 5 | root → lane1.bottom(B).parents=[root]、一致 → レーン 1 に追加。親なし → レーン 1 を解放 | `[lane4:[E,C]]` |

配置結果:

```
レーン:  1      4
行 0:    D      E
行 1:    B      C
行 2:    root
```

エッジ:

| 接続 | 種類 |
|---|---|
| D → B | レーン 1 内（縦） |
| B → root | レーン 1 内（縦） |
| E → C | レーン 4 内（縦） |
| C → root | レーン 4 → レーン 1（斜め・1 行分） |

`C → root` が列をまたぐのは、feature ブランチが main の祖先に収束する様子を表す。
